## Phase Goal

**As a** Telu user, **I want to** turn a completed meeting into trustworthy typed knowledge, inspect its exact evidence, and control what becomes eligible for future use, **so that** only reviewed knowledge I can trace to the exact transcript words is carried into later meetings.

<objective>
This plan is step 0 of closing SC5 / KNOW-07, under the user's decision of 2026-09-28 ("Real-meeting pilot first": a real-meeting pilot, then the threshold declaration, then a held-out representative evaluation). It prepares the tooling so that a pilot can never pass as, or overlap with, the representative evaluation. Every scored report states what kind of run produced it, and the status module counts a representative report only if it is labeled representative and shares no meeting with the committed real-meeting pilot.

Purpose: The user requires the pilot to be distinguishable in content and the pilot and held-out sets to be disjoint, both checked rather than attested. The report had no field recording its run type, and the executor may not hand-edit reports, so the label has to come from the CLI.
Output: `score --kind`, the `evaluationKind` report field, and the status reasons `representative_kind_mismatch` and `representative_not_held_out`.

Tooling finding: scoring against undeclared thresholds already works. Null leaves pass `Thresholds::validate`, and `gate()` returns `undeclared`, or `fail` when 02-31's input minimums (5 representative, 1 insufficient-evidence, 1 degraded-capture) are not met. A pilot gate can never be `pass`. No change is needed there.

Supersession: 02-32-SUMMARY.md (keep-open) and 02-33-SUMMARY.md (halted) stay unchanged as history. 02-35 (pilot), 02-36 (declaration) and 02-37 (held-out evaluation) carry the rest, and none of them depends on 02-33.
</objective>
