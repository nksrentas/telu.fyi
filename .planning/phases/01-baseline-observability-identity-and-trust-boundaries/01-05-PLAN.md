## Phase Goal

**As a** Telu user or maintainer, **I want to** rely on a measured, recoverable desktop foundation with one meeting identity and explicit local, LAN, or remote data boundaries, **so that** I can trust the foundation before Telu adds product intelligence.

<objective>
Promote the effective processing route to a Rust-owned capability contract and show it consistently in settings and at data-bearing actions without silent fallback.

Purpose: Make every local, LAN, or remote claim match the actual configured destination and preserve user choice on failure.
Output: Route resolver/DTO, provider validation changes, shared boundary UI, and action-scoped unavailable handling.
</objective>

</assumption_delta_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Provider configuration → Rust resolver | Configured endpoints/brands are untrusted until parsed, sanitized, and classified. |
| Rust route contract → provider dispatch | The validated effective destination must match the displayed/snapshotted contract. |
| Rust DTO → trust UI | React renders but cannot infer or strengthen locality. |

## STRIDE Threat Register (ASVS L1; High blocks)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-05-01 | Spoofing / Information disclosure | custom/Ollama endpoint classification | high | mitigate | Parse/resolve effective origin, sanitize credentials/path, classify loopback/private/public, and fail on material change. |
| T-05-02 | Tampering | provider fallback | high | mitigate | Remove config-error substitution; bind dispatch to confirmed route/provider and test failure preserves choice. |
| T-05-03 | Information disclosure | route logs/UI | high | mitigate | Emit sanitized origin only; strip credentials/query/fragment/sensitive path; redaction tests block regressions. |
| T-05-04 | Repudiation | route shown versus route used | high | mitigate | Snapshot the effective route per meeting/run and validate immediately before dispatch. |
</threat_model>
