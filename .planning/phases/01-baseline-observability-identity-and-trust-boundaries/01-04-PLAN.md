## Phase Goal

**As a** Telu user or maintainer, **I want to** rely on a measured, recoverable desktop foundation with one meeting identity and explicit local, LAN, or remote data boundaries, **so that** I can trust the foundation before Telu adds product intelligence.

<objective>
Turn interrupted-session recovery into idempotent reconciliation and make incomplete, recovered, and legacy-unverified states impossible to mistake for complete.

Purpose: Preserve useful meeting content without fabricating continuity or duplicating meetings after crash/retry.
Output: Same-ID recovery command, upgraded cache orchestration, shared completeness/gap UI, and repeat/concurrent recovery tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| IndexedDB/folder cache → Rust reconciliation | Crash-staged data is untrusted input to canonical SQLite state. |
| Reconciliation transaction → meeting projection | Durable evidence/gaps determine recovered completeness. |
| Meeting DTO → history/detail/recovery UI | Renderer must not strengthen or hide lifecycle claims. |

## STRIDE Threat Register (ASVS L1; High blocks)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-04-01 | Tampering / Repudiation | repeated recovery | high | mitigate | Stable unique keys, scoped transaction, idempotency/concurrency/interruption tests. |
| T-04-02 | Spoofing | cache meeting/evidence IDs | high | mitigate | Validate existence/foreign-key scope in Rust; reject cross-meeting and stale inputs. |
| T-04-03 | Information disclosure | recovery preview/gap reasons | medium | mitigate | Show necessary local facts; keep raw paths/content out of default technical errors. |
| T-04-04 | Tampering | completeness UI | high | mitigate | Render Rust result only; contract tests forbid UI promotion and require visible unknown/gap states. |
</threat_model>
