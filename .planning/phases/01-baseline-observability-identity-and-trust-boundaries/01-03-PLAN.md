<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Native capture → bounded transcription queue | Latency-sensitive audio work is admitted or explicitly rejected without blocking capture. |
| Queue ledger → lifecycle repository | Terminal accounting controls complete/incomplete persistence. |
| Rust snapshot → React finalization UI | Renderer displays authoritative queue and lifecycle state. |

## STRIDE Threat Register (ASVS L1; High blocks)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-01 | Denial of service | transcription queues | high | mitigate | Finite Tokio channels, non-blocking admission, explicit rejection/gaps, and overload tests. |
| T-03-02 | Tampering / Repudiation | terminal queue outcomes | high | mitigate | One terminal outcome per accepted ID plus conservation invariants and reason codes. |
| T-03-03 | Spoofing | frontend completion state | high | mitigate | Rust/SQLite lifecycle is authoritative; UI cannot infer complete from depth, silence, or elapsed time. |
| T-03-04 | Information disclosure | status/error DTOs | medium | mitigate | Expose counts, IDs, and redacted reason codes; exclude transcript/audio content and secrets. |
</threat_model>

<verification>
- Queue tests cover empty, simultaneous, equal-time, overload, closed, failure, and terminal conservation cases.
- Finalization tests cover stop on empty/shallow/full queues, deadline, failure, duplicate stop, and persistence rollback.
- Node UI contract test and frontend build cover exact copy, actions, accessibility, and removal of renderer inference.
</verification>

<success_criteria>
- Maintainers observe real queue depth and oldest age; no placeholder metric remains.
- Stop is finite and honest: complete only after terminal work and durable writes, otherwise incomplete with facts.
- Overload cannot grow transcription work without bound or silently lose rejected work.
</success_criteria>
