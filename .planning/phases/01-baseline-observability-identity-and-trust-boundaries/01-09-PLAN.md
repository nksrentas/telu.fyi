## Phase Goal

**As a** Telu user or maintainer, **I want to** rely on a measured, recoverable desktop foundation with one meeting identity and explicit local, LAN, or remote data boundaries, **so that** I can trust the foundation before Telu adds product intelligence.

<objective>
Execute the reproducible target-hardware matrix, review repeated-run evidence, and record explicit thresholds and downstream go/no-go decisions without inventing performance targets.

Purpose: Convert Phase 1 implementation into trustworthy evidence that can actually unblock—or block—later phases.
Output: Baseline CLI/manifest validator, approved reference profile, scenario protocol, local run bundles, and versioned threshold/gate decision.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Scenario manifest/reference profile → runner | Inputs determine claimed environment, workload, and expected route behavior. |
| Local bundles → aggregate/gate decision | Raw measurements become threshold and downstream readiness claims. |
| App outbound ledger → OS network observation | Two evidence sources must reconcile for the privacy canary. |

## STRIDE Threat Register (ASVS L1; High blocks)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-09-01 | Tampering / Repudiation | scenario/threshold report | high | mitigate | Versioned manifests, distinct immutable run IDs, raw bundle links/hashes, outlier retention, separate post-declaration validation. |
| T-09-02 | Spoofing | reference environment | high | mitigate | Blocking-human approval of exact fingerprint and preflight comparison before each measured run. |
| T-09-03 | Information disclosure | local evidence/report paths | high | mitigate | Redacted bundles, sanitized relative references/checksums, no credentials/content/full sensitive paths in tracked gate docs. |
| T-09-04 | Information disclosure / Repudiation | network canary | high | mitigate | Independent OS block/capture plus app attempt ledger; any unmatched attempt or missing ledger fails. |
| T-09-05 | Denial of service | overload/crash scenarios | medium | mitigate | Bounded workloads, documented cleanup/recovery, durable artifacts, and explicit abort/unknown state on unsafe environment. |
</threat_model>

</verification>
