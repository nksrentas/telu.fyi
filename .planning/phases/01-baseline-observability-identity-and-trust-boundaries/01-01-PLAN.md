## Phase Goal

**As a** Telu user or maintainer, **I want to** rely on a measured, recoverable desktop foundation with one meeting identity and explicit local, LAN, or remote data boundaries, **so that** I can trust the foundation before Telu adds product intelligence.

<objective>
Prove the brownfield walking skeleton: one real Rust-owned meeting identity travels through SQLite, the existing Tauri recording command/event boundary, React state, and local recovery metadata before capture begins.

Purpose: Remove the split-identity failure that would invalidate every later evidence, recovery, and observability claim.
Output: A forward-only identity/lifecycle migration, transactional start contract, canonical IPC payload, and same-ID recording/recovery mirrors.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| React → Tauri start command | Renderer supplies title/device preferences but cannot supply canonical identity or lifecycle. |
| Rust → SQLite/filesystem | Rust persists identity and creates app-data recording paths before capture. |
| SQLite → IndexedDB/React | Canonical durable state is mirrored into reload/recovery caches. |

## STRIDE Threat Register (ASVS L1; High blocks)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-01 | Spoofing / Tampering | start command and `TranscriptContext` | high | mitigate | Rust mints IDs, validates current lifecycle, and tests reject renderer-created/remapped IDs. |
| T-01-02 | Tampering | recording directory creation | high | mitigate | Use UUID path components and Tauri app-data resolution; titles are display metadata only. |
| T-01-03 | Repudiation | legacy lifecycle migration | medium | mitigate | Preserve explicit completion-unverified/legacy reason rather than asserting unsupported history. |
| T-01-04 | Information disclosure | start/event logging | medium | mitigate | Log IDs and typed error codes only; do not log transcript content, secrets, or full sensitive paths. |
</threat_model>

<verification>
- Focused Rust tests prove one pre-capture ID, transactional failure behavior, and mirror continuity.
- Frontend production build proves the typed IPC payload and context/cache consumers compile.
- Fresh and representative legacy databases migrate forward without rewriting historical IDs or claiming verified completion.
</verification>

<success_criteria>
- A user-visible recording lifecycle is backed by one durable Rust ID before audio capture.
- Repeated renderer setup consumes the same ID and cannot create another logical meeting.
- SQLite remains canonical; recording metadata and IndexedDB are mirrors/caches.
</success_criteria>
