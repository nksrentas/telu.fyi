**As a** Telu user or maintainer, **I want to** rely on a measured, recoverable desktop foundation with one meeting identity and explicit local, LAN, or remote data boundaries, **so that** I can trust the foundation before Telu adds product intelligence.

<objective>
Make finalized transcript segments durable, stable, and measurable while keeping partial text explicitly provisional.

Purpose: Give later knowledge and recovery features canonical evidence that survives retries and renderer crashes.
Output: Evidence migration/upsert, persist-before-publish worker flow, provisional/final frontend contract, and correlated UI acknowledgement.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Transcription worker → SQLite | Model output becomes durable canonical evidence only after validation and upsert. |
| Rust event → React renderer | Canonical evidence crosses IPC with stable identity/finality metadata. |
| React → acknowledgement command | Renderer returns an opaque token to close the timing span. |

## STRIDE Threat Register (ASVS L1; High blocks)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-01 | Tampering / Repudiation | evidence upsert | high | mitigate | Unique stable evidence/source keys, transactional upsert, and retry/redelivery tests. |
| T-02-02 | Spoofing | UI acknowledgement token | medium | mitigate | Opaque single-use token bound to meeting/evidence/run and rejected when unknown/stale. |
| T-02-03 | Information disclosure | worker/frontend logs | high | mitigate | Remove transcript samples from diagnostics; log allowlisted IDs, lengths, outcomes, and redacted errors only. |
| T-02-04 | Tampering | provisional/final UI state | high | mitigate | Finality comes from Rust DTO; IndexedDB separates provisional display data from canonical recovery evidence. |
</threat_model>
